# Общие проекты C1 и C2

Модуль установлен внутри общего UI-помощника ChatGPT Desktop App. C1 и C2 используют один каталог местных проектов и одно дерево папок. Открывайте приложение прежними ярлыками C1/C2; отдельный запуск синхронизатора не требуется.

## Обычная работа

Добавление, переименование, изменение рабочих каталогов и явное удаление местного проекта передаются между C1 и C2. Порядок проектов в нашем представлении сайдбара также общий. Для каждого профиля сохраняется собственный штатный ID проекта.

Создание, переименование, перенос и удаление папки, а также назначение проекта в папку сразу меняют общий каталог. Дерево получают все доступные окна обоих профилей. Раскрытие веток сохраняется отдельно для каждого профиля. Управление папками описано в [Folders](C:/work/research/provision/code/AI/products/OpenAI/ChatGPT/Desktop/Addons/code/Folders/KB/README.md#управление).

Рядом с кнопкой добавления папки находится **⇄**. Она показывает состояние подключений, ожидающие изменения и конфликты. Закрытый профиль получает изменения после открытия. При несовместимых одновременных изменениях можно выбрать общее значение либо значение конкретного профиля. Простое исчезновение проекта из ответа сервиса не считается общей командой удаления: требуется выбрать восстановление либо удаление для всех.

При создании проекта штатный запрос **Trust this folder?** может появиться в исходном аккаунте. **В другом аккаунте повторное подтверждение для новой копии не требуется:** если такие же рабочие каталоги уже зарегистрированы в исходном профиле, помощник использует штатный режим `upsertLocal(..., 'restore')`, применяемый самим приложением для восстановления проекта. Происхождение записывается в операции как `approvedBy`; одни ручные правки общего каталога не дают этого подтверждения. [Реализация выбора](C:/work/research/provision/code/AI/products/OpenAI/ChatGPT/Desktop/Addons/code/Shared-Projects/code/catalog.mjs), [реализация вызова](C:/work/research/provision/code/AI/products/OpenAI/ChatGPT/Desktop/Addons/code/Shared-Projects/code/desktop.mjs).

Создание и перенос виртуальных папок сайдбара обходятся без Trust во всех профилях. Они меняют общий JSON, а не доступ к рабочим каталогам.

При добавлении новых рабочих каталогов к уже существующему проекту приложение по-прежнему использует `editLocal` со своей проверкой. Если приложение всё же требует подтверждение, помощник сохраняет одну ожидающую операцию и продолжает после ответа; ожидание не ограничено таймаутом CDP. Если сохранение отменено, получение изменений этим профилем приостанавливается до кнопки **Повторить** в окне ⇄. Такая пауза сохраняется после перезапуска помощника. Общие настройки проверки папок и выполнения команд не отключаются.

Общими становятся местные регистрации проектов и папки сайдбара. Авторизация, лимиты и чаты остаются у своих профилей. Модуль не копирует рабочие файлы и не переносит историю между аккаунтами. Облачные проекты ChatGPT с `chatGptBacking`, `chatGptBackingCreation` или `retiredChatGptBacking` исключены из каталога.

Сервис вызывается внутри уже работающего Desktop App. Дополнительный сервер CLI не запускается. Модуль использует существующие отладочные порты C1:9223 и C2:9224, а управление помощником — прежний локальный именованный канал Windows. Файлы авторизации не читаются и не объединяются.

Каталог содержит общие UUID, соответствия штатным ID каждого профиля, последнюю наблюдавшуюся версию, ожидающие операции и конфликты. Для новой реплики ID сохраняется до вызова приложения. Перед записью проверяется, что целевой проект не изменился. Применение собственного изменения не порождает повторную общую команду. Результат перечитывается; потерянное подтверждение восстанавливается по фактическому состоянию.

Исходные `ui-folders.json` в профилях оставлены как данные прежней конфигурации. Активный помощник их больше не использует для текущего дерева. Повреждённый общий JSON не заменяется пустым каталогом: запись останавливается с ошибкой. Для исправления остановите помощник, проверьте файл и его `.bak`, затем запустите помощник снова.

## Обновления приложения

**После обычного совместимого обновления вручную запускать Upgrade не требуется.** Код помощника и каталог находятся вне установки приложения; `app.asar` не изменяется. Прежние ярлыки запускают помощник, а при появлении нового окна он подключается автоматически.

Адаптер заново находит актуальный `app-initial-*.js`, экспорт сервиса проектов и его изменившиеся минифицированные имена.  
Начиная со сборки `26.1027.3384.0` (`appVersion: 26.1027.30824`), где сборщик переведён на Rolldown и точка входа `index-*.js` загружает `app-main-*.js` → `app-initial-*.js` + `app-runtime-*.js` → `app-primary-*.js`, `scanBootstrap` в `desktop.mjs` обходит цепочку `index-*.js` / `app-main-*.js` / `app-runtime-*.js`, поддерживая как прежнюю, так и новую структуру бандлов.  
Перед подключением проверяются структура доступа, ожидаемые операции и формат читаемых проектов.  
Обновление хешей ресурсов само по себе не требует переписывать пути.

Если OpenAI изменит внутренний контракт, способ доступа или отладочный интерфейс, может потребоваться адаптация кода. Неоднозначное обнаружение или несовместимый формат приводят к паузе с ошибкой в ⇄ и журнале. Автоматическую совместимость с любой будущей версией гарантировать нельзя. Основные точки зависимости видны в [поиске и проверках адаптера](C:/work/research/provision/code/AI/products/OpenAI/ChatGPT/Desktop/Addons/code/Shared-Projects/code/desktop.mjs).

Это продолжает существующий способ подключения [UI](C:/work/research/provision/code/AI/products/OpenAI/ChatGPT/Desktop/Addons/code/UI/KB/README.md#устройство). В отличие от патча Antigravity `Upgrade`, повторного изменения файлов установленного приложения здесь нет.

## Регистрация из локальных инструментов

Локальные производители проектов, включая Upwork, используют именованный канал существующего UI-помощника через экспорт `control` из UI/code/manage.mjs. Для JSON из stdin есть CLI `manage.mjs request`.

Запрос `shared-ensure-project` содержит `profile: C1|C2` и `project: {name, rootPaths, folderPath}`. Рабочие каталоги должны существовать; точное нормализованное соответствие rootPaths повторно использует общий проект и его нативные ID, сохраняя существующее имя. Ветка folderPath создаётся идемпотентно и получает назначение в одной транзакции CatalogStore. Неоднозначность и конфликт диагностируются до записи.

Ответ содержит shared_id, folder_id, folder_path, profiles с отдельными project_id/ready и complete/status для исходного профиля. `pending` означает сохранённый запрос; окончание проверяется повторным идемпотентным вызовом либо `shared-registration` с sharedId/profile. Квитанция регистрации включает также accounts с состоянием подключений.

Для нового проекта сначала проходит настоящая регистрация исходного профиля; остальные ждут наблюдаемого подтверждения его каталогов. После этого применяется существующий механизм provenance/restore. Отмена Trust и закрытый профиль сохраняют прежнее поведение очереди. Инструмент не пишет catalog.json или файлы профилей самостоятельно.

## Отключение и восстановление

Для временного отключения до следующего открытия ярлыка:

```powershell
& 'C:/tools/nodejs/node.exe' 'C:/work/research/provision/code/AI/products/OpenAI/ChatGPT/Desktop/Addons/code/UI/code/manage.mjs' stop
```

Остановка снимает наблюдение, папки и CSS с открытых окон. Штатные проекты, уже созданные в профилях, и общий каталог остаются. Постоянное отключение запуска — через [UI/code/uninstall.ps1](C:/work/research/provision/code/AI/products/OpenAI/ChatGPT/Desktop/Addons/code/UI/code/uninstall.ps1); он восстанавливает прежние обёртки и ярлык C2 и не удаляет каталог.

Если потребуется отменить именно миграцию, ориентируйтесь на сохранённый план и восстанавливайте выбранные регистрации и раскладку адресно. Полное восстановление старой SQLite-базы откатит последующую работу; обычное отключение помощника такого восстановления не выполняет.
